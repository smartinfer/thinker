# Inference architecture advance — 2026-10-07

Status: implemented and offline verified; see INFERENCE_PLANNING.md and INFERENCE_ARCHITECTURE_RESULTS_2026-10-07.md. This plan supersedes the unimplemented strict-V2 prototype. Extend the existing Model-Turn V1 contract with an opt-in policy; retain old caller behavior.

## Six goals

1. Concrete-model capability profiles distinguish NATIVE / EMULATED / UNSUPPORTED, with provenance and explicit thinking settings.
2. A pure planner resolves requirements and authorized workarounds before submission; its immutable plan binds route, model, schema, prompt, settings and capability snapshot.
3. Provider lowering, response lifting and error classification are functions. Network/file effects live at the edge.
4. Preserve final answer vs reasoning-artifact boundaries, termination, known/unknown usage, raw transport audit and model identity. Never certify financial semantics.
5. Workarounds are named, preselected and caller-authorized. No reactive downgrade, retry or substitution in the planned path. Initial optional workaround: JSON_PROMPT (weaker than native schema).
6. Scenario-level conformance tests cover the entire prepare → execute → normalize flow for OpenAI, Anthropic and Gemini. No live providers in tests.

## Functional prototypes

```python
plan_turn(request, registry_call, capability_profile) -> InferencePlan
lower_request(request, plan) -> PreparedInference
lift_response(prepared, http_status, raw_body) -> InferenceOutcome
async execute_inference(prepared, *, credentials, send=None, audit_directory=None,
                        cancel_event=None) -> InferenceOutcome
```

The shared request remains ModelTurnRequest. A new optional `inference_policy` opts in. Profiles are host supplied, never generated by the model. The runtime resolves an exact registry call, builds a plan, executes one attempt, then exposes the outcome through ModelTurnResponse. Existing V1 best-effort behavior remains available but is not suitable for strict evaluation.

## Acceptance scenarios (written before implementation)

- Each provider: common request lowers faithfully, final JSON excludes thought text, no tools appear, usage and resolved model survive.
- Capabilities/controls: unsupported native schema, identity, output budget or thinking setting rejects before HTTP; explicit emulation is visibly weaker.
- Schema HTTP rejection receives one attempt, never fallback; prompt and schema hashes remain fixed.
- Completed invalid JSON differs from refusal, incomplete, HTTP error and timeout; known usage survives invalid output.
- Optional immutable audit captures actual payload/response without credentials; collision fails before HTTP; cancellation does not assert remote cancellation.
- Runtime/service integration preserves old caller behavior and supports the new path with a concrete host profile.

Scope: no new agent runtime, automatic routing optimizer, financial ontology, solver, live benchmark, production Gandiva/Spartacus migration, vision or streaming execution. Declared capabilities do not imply implemented orchestration. Costs remain explicitly unknown unless independently supported pricing is available.
